# Архитектура многоагентной системы SafeSchool

Практическая часть магистерской диссертации «Модели компьютерного зрения и
машинного обучения для выявления нарушений безопасности и жестокого обращения с
детьми в образовательных учреждениях». Ассайнмент 2.

## 1. Тема и обоснование многоагентного подхода

Система анализирует видео с камер наблюдения в школе и определяет, является ли
происходящее нарушением безопасности, после чего скрывает лица и передаёт
инцидент на соответствующий уровень реагирования.

Задачу решает **команда агентов, а не один агент**, потому что подзадачи
предъявляют несовместимые требования, а две из них являются свойствами
корректности, которые при объединении агентов просто исчезают:

| Подзадача | Характер | Почему нужен отдельный агент |
|---|---|---|
| Декодирование и сегментация видео | детерминированная, I/O | тратить токены LLM на неё бессмысленно, а воспроизводимый шаг стал бы невоспроизводимым |
| Детекция людей, поз, оружия | численная модель на GPU | собственный батчинг и пороги уверенности; сбой восприятия должен отличаться в логах от сбоя рассуждения |
| Агрегация движения по трекам | численная, временная | иной режим отказа: потерянные треки — это не ошибка рассуждения |
| Интерпретация: нарушение ли это **в отношении ребёнка** | поиск и рассуждение по политике и литературе | нужна опора на источники, и агент не должен видеть лица |
| Отсев ложных срабатываний | состязательная самопроверка | **агент, проверяющий собственный вывод, наследует породившее ошибку допущение.** Независимость — суть этого этапа |
| Обезличивание и эскалация | политика, аудируемость | **ровно одно место для аудита утечки** и ровно одно место, откуда что-либо покидает систему |

Последние два пункта — главный аргумент. Это не разделение ради
производительности, а структурные гарантии.

## 2. Схема взаимодействия

Используется **гибрид трёх схем** из техзадания — конвейер, оркестратор и общая
память:

- **Конвейер** — между шестью этапами существует реальная зависимость по данным:
  движение нельзя вычислить до детекции, политику нельзя применить до появления
  оценки. Порядок задан структурой задачи, а не соглашением.
- **Оркестратор** — кто-то должен владеть бюджетом, повторными попытками и
  единственным решением о потоке управления (нужен ли повторный прогон).
- **Общая память (доска CaseFile)** — агент-проверяющий должен видеть *все*
  артефакты предыдущих этапов, чтобы проверить цепочку.

Иерархия не используется: при шести этапах с линейной зависимостью дерево
добавило бы только косвенность.

```
CaseRequest
   │
   ▼  OrchestratorAgent: строит план, открывает CaseFile, запускает бюджет
   │
   ├─1─► IngestAgent ──────────► ClipSet          (декодирование, нарезка, кадры)
   ├─2─► VisionDetectorAgent ──► DetectionSet     (люди, позы, оружие)
   ├─3─► MotionAnalystAgent ───► MotionAssessment (треки, признаки, оценка)
   ├─4─► ContextAgent ─────────► ContextVerdict   (политика + литература)
   ├─5─► VerifierAgent ────────► Verification     (независимый аудит)
   │        │
   │        └── вердикт «rerun» ──► назад на этап 2 с пониженным порогом
   │                                (не более одного раза, затем решение)
   │
   └─6─► PrivacyReportAgent ───► IncidentReport   (обезличивание, отчёт, эскалация)
```

## 3. Таблица агентов

| № | Агент | Роль | Вход | Выход | Инструменты (≤5) | Критерий завершения |
|---|---|---|---|---|---|---|
| 0 | `OrchestratorAgent` | Планирует последовательность этапов, маршрутизирует сообщения, следит за лимитами. **Предметную работу не выполняет.** | `CaseRequest` | `Plan` | хранилище дел, логгер | план выполнен либо прерван с указанием причины |
| 1 | `IngestAgent` | Декодирует видео, нарезает на клипы, извлекает ключевые кадры | путь к видео | `ClipSet` | `video.probe`, `video.extract_keyframes`, `fixtures.load` | зарегистрирован хотя бы один корректный клип |
| 2 | `VisionDetectorAgent` | Люди, позы (17 точек) и оружиеподобные объекты по кадрам | `ClipSet` | `DetectionSet` | `yolo.load_model`, `yolo.detect_poses`, `yolo.detect_objects`, `fixtures.load` | у каждого клипа есть запись детекций (пустая допустима) |
| 3 | `MotionAnalystAgent` | Связывает детекции в треки, считает признаки движения и оценку | `DetectionSet` | `MotionAssessment` | `tracking.assign_ids`, `features.extract_features`, `features.score` | у каждого клипа оценка в [0,1] и вектор признаков |
| 4 | `ContextAgent` | Интерпретирует по школьной политике и обзорной литературе | `MotionAssessment` | `ContextVerdict` | `policy_kb.candidate_clauses`, `corpus_retriever.search`, `llm.complete_json` | есть категория, уровень 1–4 и ≥1 ссылка на источник |
| 5 | `VerifierAgent` | Независимо проверяет цепочку: принять / отклонить / повторить | `ContextVerdict` | `Verification` | `rules.consistency_checks`, `llm.complete_json`, `case_store.read_artifacts` | вынесен вердикт с уверенностью и списком замечаний |
| 6 | `PrivacyReportAgent` | Скрывает лица, формирует отчёт, эскалирует по политике | `Verification` | `IncidentReport` | `blur.redact_frame`, `policy_kb.escalation_tier`, `report.render`, `notifier.notify` | отчёты созданы и ссылаются только на обезличенные кадры |

Роли не дублируются: у каждого агента свой этап, проверяется тестом
`test_agent_team_meets_the_specification`.

## 4. Формат сообщений

Все полезные нагрузки — модели pydantic с `extra="forbid"`, сериализуемые в JSON
внутри конверта `AgentMessage`. Опечатка в имени поля приводит к ошибке на
границе агента, а не к порче данных на три этапа позже.

```python
class AgentMessage(BaseModel):
    msg_id: str
    case_id: str
    sender: str
    recipient: str
    type: MessageType
    payload: dict[str, Any]          # Payload, выгруженный в JSON
    created_at: datetime
    attempt: int = 1
    overrides: dict[str, Any] = {}   # управляющие данные — не внутри payload
```

Поле `overrides` появилось не случайно: пониженный порог при повторном прогоне —
это управляющая информация, а не факт об инциденте. Попытка положить его внутрь
`ClipSet` ломала строгую схему — что и произошло при разработке.

## 5. Внешние инструменты и источники данных (требуется ≥2, реализовано 5)

1. **Anthropic Claude API** — рассуждение в агентах 4 и 5
2. **Предобученные веса YOLOv8n / YOLOv8n-pose** — детекция и оценка поз
3. **Корпус литературы диссертации** — 50 рассмотренных статей
   (`matrix_literature.csv` и извлечённые полные тексты), индекс BM25
4. **База знаний школьной политики безопасности** — `data/policy/school_safety_policy.json`
5. **Хранилище дел SQLite** — явное состояние задачи

## 7. Надёжность и безопасность

| Риск | Механизм | Где реализовано |
|---|---|---|
| Бесконечное выполнение | лимит шагов и лимит времени, проверка перед каждым агентом | `runtime.Budget` |
| Зацикливание между агентами | одинаковый вход дважды — прерывание | `runtime.LoopGuard` |
| Циклы повторных прогонов | не более одного повтора, затем обязательное решение с указанием причины | `VerifierAgent` |
| Временные сбои | 3 попытки с экспоненциальной задержкой | `runtime.Agent.execute` |
| Неустранимые сбои | немедленный отказ, бюджет не расходуется | `SafeSchoolError.recoverable` |
| Аудит | каждый вызов логируется средой выполнения, а не агентом | `logging_bus.CallLogger` |
| Утечка ключей | ключи вычищаются перед записью | `logging_bus._scrub` |
| Ключи API в коде | только переменные окружения и `.env` в `.gitignore` | `config.py` |

## 8. Прототип и тестовые сценарии

Реализованы и взаимодействуют **все шесть** рабочих агентов (при требовании
«минимум два»). Команда `safeschool demo` — 10 сценариев из 10 соответствуют
ожиданиям.

| сценарий | вход | ожидание | результат |
|---|---|---|---|
| `corridor_walking` | реальное видео, люди идут по коридору | тревоги нет | `no_violation` / log |
| `crowded_aisle` | реальное видео, несколько человек в узком проходе | тревоги нет | `no_violation` / log |
| `single_person` | реальное видео, один человек | нет вердикта о взаимодействии | `no_violation` / log |
| `empty_scene` | синтезированное, людей нет | тревоги нет | `no_violation` / log |
| `corrupt_file` | повреждённый файл | корректный отказ | `StageFailed`, понятное сообщение |
| `missing_file` | несуществующий путь | корректный отказ | `StageFailed`, понятное сообщение |
| `fixture_fight` | запись драки двух человек | эскалация | `physical_violence` / notify_admin |
| `fixture_weapon` | запись с оружиеподобным объектом | экстренный уровень | `weapon_threat` / emergency |
| `fixture_adult_child` | запись с большой разницей роста | защита ребёнка | `adult_on_child_abuse` / emergency |
| `fixture_rough_play` | активная, но взаимная возня | **без тревоги о насилии** | `bullying_nonphysical` / notify_staff |

Первые четыре сценария — наиболее важные: это реальное видео, где правильное
поведение системы — молчание. Система, не умеющая молчать, в школе неприменима.

Дополнительно: 43 модульных теста (`pytest`).

## 9. Связь с результатами обзора литературы (этап 1)

| Вывод обзора | Как учтён в системе |
|---|---|
| Приватность почти не обсуждается — 2 статьи из 50 | Отдельный агент владеет обезличиванием и является единственным компонентом, работающим с изображениями |
| Датасеты содержат взрослых вне образовательной среды | Отдельный пункт политики и проверка разницы роста с учётом перспективы специально для случая «взрослый — ребёнок» |
| Доминируют accuracy и AUC, ложные срабатывания не исследуются | Независимый проверяющий оценивает риск ложного срабатывания; оценка интерпретируема; «похожие на насилие, но безобидные» сценарии включены в тесты |

## 10. Известные ограничения

- Оценка насилия — **откалиброванная эвристика, а не обученная модель**. Она
  уверенно разделяет имеющиеся сценарии, но не проверена на размеченном
  бенчмарке. Обучение временного классификатора — следующий этап; интерфейс
  спроектирован так, чтобы его не пришлось менять.
- Положительные сценарии работают на **синтезированных фикстурах**: Hockey
  Fights, RWF-2000 и UCF-Crime требуют принятия условий и здесь не
  распространяются.
- Связывание треков — жадное сопоставление по IoU, пригодное для коротких
  роликов и небольшого числа людей.
- Отделение возни от настоящей драки по одному лишь движению объективно трудно —
  это и есть основной источник ложных срабатываний по данным обзора.
- База знаний политики носит **иллюстративный характер**; при внедрении
  потребуется реальный документ учреждения.
